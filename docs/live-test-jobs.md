# Greenhouse live test jobs

Job lists are checked manually or generated by `scripts/find_greenhouse_jobs.py`
(it searches the boards in `data/greenhouse_boards.txt`, skips jobs already used
in any `data/test_jobs*.yaml` or the submission ledger, and writes a new list).
Availability must be checked again before each run.

| File | Contents |
| --- | --- |
| `data/test_jobs.yaml` | Current batch (14 jobs); `default_job` selects the default (`job_01`, Anthropic) |
| `data/test_jobs_batch1.yaml`, `data/test_jobs_batch2.yaml` | Earlier batches, kept for reference |
| `tests/fixtures/test_jobs.yaml` | Stable fixture used by the test suite |

The code reads `data/test_jobs.yaml`. Set `default_job` to a key in its `jobs`
mapping to choose the default. Run it with:

```sh
.venv/bin/python -B main.py
```

Override the configured default for one run with a URL, run every configured
job with `--all-test-jobs`, or add `--ignore-score` for a fill-only dry run:

```sh
.venv/bin/python -B main.py 'https://job-boards.greenhouse.io/reddit/jobs/8282760'
```

The workflow must honor its filters and score thresholds. Do not force a SKIP
into form filling to obtain a test result. Test runs must be dry runs: do not
pass `--submit`. Submission is allowed only when explicitly requested for a
specific job, and then only through the gate (score AUTO_APPLY, readiness
READY, no generated content, not already in `data/submissions.json`).
Unknown salary, authorization, sponsorship, relocation, and personal-history
answers must stay for human review unless an approved fact exists in `data/`.
Questions requiring candidate evidence (e.g. a sports-fan question) are never
answered with an invented personal connection.

The CLI currently closes its browser at the end. A persistent human handoff is
still an MVP gap; live assisted tests may hold cleanup until the human is done.
